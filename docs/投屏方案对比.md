# 投屏方案对比备忘

整理自 2026-10 的调研与实测，方便以后重新对比时有一个基线。厂商功能随机型、系统版本、地区差别很大，用之前先按文末的来源重查一遍。

一句话结论：**同品牌手机配同品牌电脑的办公场景，厂商协同最省心；跨品牌设备、掌机和方屏、小屏放大、多应用桌面，是水月清影的主场。** 离我们最近的对手不是手机助手，而是 QtScrcpy、Escrcpy 这类 scrcpy 图形壳。

## 先分清三种"投屏"

**视频 App 里那个"TV"按钮**（爱奇艺、腾讯、优酷）根本不是在投画面。手机只把视频链接发给电视，电视自己下载解码播放，手机该干嘛干嘛。分辨率既不由手机定，也不存在"手机侧自适应放大"——手机压根没参与出图，黑边来自片源本身（比如 2.35:1 的电影放在 16:9 电视上）。

**系统自带无线投屏、以及爱投屏/乐播的镜像模式**，是被协议锁死的那一套。镜像投屏编码时的输出分辨率是固定的，跟手机横屏竖屏、什么比例无关；手机是 21:9、电视是 16:9，就在固定尺寸的帧里居中，多出来的地方填黑。荣耀官方写明"电视端显示的内容长宽比和手机一致，所以上下有黑边"；华为的例子最能说明问题——MateView 是 3:2，协议不支持这个比例，它的解法是拉伸放大画面，代价是人物纵向变形。厂商宣传的"填充模式""拉伸模式""自适应比例"，本质都是在已经编好的那一帧里放大或裁边，不是按你的显示设备重新出一版画面。

**远程桌面类**（RustDesk、向日葵、ToDesk）要在手机装被控 App、给一堆权限，后台容易被系统杀掉；它们优先保流畅、砍画质，画面发灰、拖动明显；而且分辨率同样由手机那边定死，电脑只能收到多大显示多大。它们解决不了"按显示器尺寸自适应放大"这件事。

**我们走的这条**是设备调试通道：把目标尺寸下发给设备，让设备按那个尺寸重新渲染界面（是真的重画，字是清晰的，不是拉伸），再读回设备实际接受的尺寸来修正档位。掌机那条实测最典型：给 1920×1080，它最宽只肯到物理屏的两倍，程序读到 1440×810 就把档位改成 1440×810，预览跟着重算。这个"改系统显示参数"的能力是调试通道独有的，投屏协议层和远程桌面都拿不到。

## 横向对比

| 方案 | 最适合 | 强项 | 短板 |
|---|---|---|---|
| **水月清影** | 跨品牌设备、掌机/方屏、小屏放大、多应用桌面 | 品牌无关；设备端重绘的高清渲染；每应用一块虚拟屏；参数自动还原；本地免费无账号；中文界面 + 无线发现和找回 | 首次要开开发者选项/ADB；没有通知、通话、短信生态；选物理键盘那一路仍会收起软键盘；部分高级能力没包装 |
| **scrcpy / QtScrcpy / Escrcpy** | 开发者、极客、多设备群控 | 低延迟、免费开源、功能全；QtScrcpy 支持多设备，Escrcpy 有图形界面 | 命令行和配置门槛；没有分辨率模板、参数还原和应用投屏这套流程 |
| **微软 Phone Link** | 三星/荣耀/OPPO/小米等列表内机型 + Win11 | 系统自带，通知、通话、短信、部分应用、跨设备剪贴板 | 机型白名单；要微软账号；不能改分辨率和虚拟屏；国内部分功能受限 |
| **华为 / 荣耀多屏协同** | 华为荣耀手机 + 华为电脑 | 生态最深：多窗口、拖文件、剪贴板、应用接续、调用摄像头麦克风 | 强绑品牌；非华为电脑功能受限；不能改分辨率 |
| **小米互联 / HyperConnect** | 小米 Redmi + Windows 11 | 通用版不限电脑品牌；镜像、文件、剪贴板 | 深度功能仍偏小米电脑；不能改分辨率；限 Win11 |
| **OPPO / realme / 一加 跨屏互联** | 同品牌手机 + Windows/Mac | 镜像、拖文件、剪贴板、通知、电脑输入法直接输入 | 品牌绑定；不能改分辨率；老机型老电脑发现不稳定；会占用 adb 端口 |
| **vivo / iQOO 办公套件** | vivo iQOO + Windows 10+/Mac | 不强制微软账号；投屏、文件、剪贴板 | 品牌绑定；游戏延迟一般；不能改分辨率 |
| **三星 DeX** | 三星手机 + Windows 或外接显示器 | 真正的桌面模式、键鼠、通知通话 | 品牌绑定；偏"接显示器"而不是通用投屏；不能自由改分辨率 |
| **AirDroid Cast / ApowerMirror / Vysor** | 临时演示、远程、跨 iOS 和安卓 | 上手快、可远程、网页接收 | 免费版有水印、时长或画质限制；要账号和云；延迟高于本地方案；不能改分辨率 |

> 共同点值得单独记一句：**"不能改分辨率"是所有厂商协同和商业投屏的天花板**，因为要改的是设备系统显示参数，不是投屏协议能碰的层。

## 我们的优势

1. **设备覆盖是真差异**。华为小米 OPPO 的协同只认自家手机；RG Rotate、Anbernic 这类掌机、方屏设备、老平板根本不在名单里。scrcpy 能连，但没有中文界面、无线配对和还原流程。
2. **高清渲染独一份**。不是把 720 的图拉大，而是让设备按 1080/2K 重新渲染再投。对小屏、方屏、掌机来说，这是"从能看变成能办公"的差别。
3. **应用虚拟屏 + 多窗口**。每个应用一块独立虚拟屏、在电脑上并排，是电脑桌面模式，不是单纯镜像一台手机。厂商的多窗口多在手机和平板内部，不在 Windows 桌面上。
4. **本地、免费、无账号**。画面不出局域网，不注册、不订阅、没有广告。
5. **把 scrcpy 的坑补成了产品**。无线扫描配对重连、IP 或端口变化后找回、改分辨率后的自动还原和兜底、应用列表直达、窗口置顶和无边框。断开的瞬间设备若已经掉线，还原会失败——程序会把这件事记下来，等同一台机器（按 IP 认，端口变了也算）重新连上时自动补；一直没回来的话界面会提醒一次，并指出「显示还原」页手动还原这条路。投屏期间默认让设备保持活跃（引擎的"保持屏幕常亮"），因为无线投屏最常见的掉线原因是设备自己息屏休眠、Wi-Fi 跟着断；想省电可以在「更多参数」里关掉。投屏异常断开（不是用户自己关的）时会等设备回到网络、用原参数自动重连一次，失败才提示；如果它换了端口，不自动换地址去连，交回给用户确认。每次异常掉线还会自动留一份现场：设备端最近几分钟日志、Wi-Fi 状态和投屏进程最后的输出，存进程序数据目录的 logs 文件夹，界面上会提示文件位置。

## 我们的劣势

1. **首次设置门槛高**。开发者选项、USB 调试、无线调试配对，对普通用户仍是劝退点；厂商协同基本是靠近或扫码即用。
2. **没有系统级生态**。通知、通话、短信、文件管理、调用手机摄像头麦克风，这些厂商助手能做，我们做不了。
3. **输入法已经不再是硬短板**。键盘通道默认走系统注入，不再顶掉手机软键盘，选中输入框后电脑上直接打中文能上屏；虚拟屏那一路也带上了输入法位置策略，键盘弹在同一块屏。选「物理键盘」时仍会收起软键盘（这是安卓行为），要打字就切回系统注入。
4. **高级能力没露出**。音频、摄像头、录制、手柄、OTG、群控这些底层已有能力，界面上大多没有入口，QtScrcpy 和 Escrcpy 在这方面更全。
5. **平台和远程受限**。只支持 64 位 Windows，依赖 WebView2；没有 Mac、Linux、iOS，也没有公网远程。
6. **虚拟屏兼容性和维护成本**。部分应用强制回主屏、部分系统不支持虚拟屏操作、输入法位置要显式指定（已经带上）；这些是安卓侧的坑，要逐台设备兜，而且是一个人维护，节奏比不过厂商和商业产品。

## 打法

- 不跟厂商助手抢"同品牌手机镜像"，那场仗比的是生态和零设置，赢不了。
- 占住"跨品牌 + 小屏方屏放大 + 多应用桌面"。目标人群是掌机、复古游戏机、方屏平板、POS 工控、老设备。宣传口径：不是把手机画面搬上电脑，是把小屏设备变成电脑上的高分屏和多窗口桌面。
- 输入法这条已经落地：默认走系统注入（软键盘不消失，电脑直接打中文）、虚拟屏带上输入法位置策略、粘贴引导和兼容粘贴兜底都写进界面。下一步值得补：剪贴板、拖文件、音频这些已有能力的界面说明，以及手柄转发——掌机玩游戏那一路要更跟手，还得靠物理键盘或手柄。
- 对 QtScrcpy 和 Escrcpy 的护城河是四样：分辨率模板、参数还原、应用虚拟屏、无线找回。它们一旦补齐，我们的差异化会变薄，这四项要持续做稳。
- 可选加法：按机型记设备配置模板、多台群控、简单文件面板。别铺太开，先把"改分辨率不翻车"做成口碑。

## 已知的外部干扰

手机助手类软件（OPPO 互联等）会在 5037 端口起自己的 adb 服务，抢走我们程序要用的那个通道，表现为无线调试连不上、扫描收不到广播。程序从 0.4.0 起会在启动和连接前检查并换回自带的那份，但这类软件仍可能占用设备连接。

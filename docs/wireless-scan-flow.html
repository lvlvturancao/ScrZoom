无线设备扫描流程

水月清影 ScreenZoom · 设计说明 · 2026-10-26
扫描收广播，同时 ping 本网段确认上次连过的设备是否还在线；只列认得的设备，端口另外算。找不回时，明确告诉用户下一步该做什么。

为什么这样设计

  • 当前网络收不到设备的 mDNS 广播（或断档），光靠广播不可行：除了收广播，还会 ping 本网段确认"上次连过的设备"是否还在线。
  • 只列广播到的和地址簿里认得的设备。网段里其它在线主机（电视、电脑、打印机、别的手机）不列出，免得干扰。
  • 端口不是"在线"的一部分：认得的主机只探一次旧端口，端口不对就交给用户点「找端口」单独扫这一台。
  • 部分开放端口不是 adb（例如 OPPO 的 46888）。adb connect 仍会提示 “connected to”，随后设备变 offline；旧逻辑把它当成成功。
  • 是否连上，不能看 adb 的提示语，只能看设备状态：只有 device 才算成功。
  • 换 IP 本身不会换端口；端口只在无线调试重启、开关或重新配对时变。两者经常一起变，所以旧端口只做一次快速尝试，不当主路径。

总流程

1点扫描 · 排除已连接设备
↓
2两条线并行 · mDNS 收广播（有就用它的端口）+ 本网段逐个 ping 探活
↓
3归属 · 广播 → 按 IP 对上地址簿 → 按 MAC 唯一对上（换了 IP）→ 其余主机不列出
↓
4认得的设备 · 只探一次旧端口：通 = 端口可用；不通 = 端口变了
↓
5没回应 / 地址被占用 · 落到「上次用过的设备」，写清原因
↓

用户点「找端口」

定位当前 IP
试旧端口和 5555
只扫这一台的端口段
验证通过 → 连上

用户点「找回这台」

按 MAC 在网段里找新 IP
试旧端口和 5555，再扫端口段
身份对得上才覆盖地址簿
统一验证：adb connect → 轮询 adb devices： device = 成功；unauthorized = 找到但需授权；持续 offline = 立即断开并判失败。

两条路径

路径何时用做什么耗时停止
普通扫描 每次点扫描 / 切到无线页 本网段 ping 探活 + mDNS 广播 + 地址簿归属 + 认得的主机探一次旧端口 5–10 秒 不需要
找端口 / 找回这台 在线但端口不通；或设备掉线、地址被占用 定位当前 IP（必要时按 MAC 找新 IP），失败只扫这一台 30–40 秒 可停止

普通扫描绝不自动扫端口段，也不会自动连接；启动自动重连失败也停下，等用户点「找端口」。

设备身份

身份优先级：serial → mDNS 实例名 → MAC（仅本网段）→ 旧地址。MAC 可能随机化，也可能因代理 ARP 重复，只当同网段线索，不单独合并设备。

{"addr":"192.168.3.12:35153",
 "mac":"42-57-f8-14-93-e1",
 "serial":"…","name":"RMX3366",
 "lastSeen":"2026-10-26T21:30:00"}

每次验证连接成功后才学习 MAC / serial / 名称；旧地址簿自动兼容，所有写回保留字段。

找端口时，顶部显示「正在为 RMX3366 找端口… 37%」和「停止」，不铺每台设备的进度。

边界

  • 只处理本机所在 IPv4 /24，网关和本机自身不列出；访客网络、AP 隔离、跨网段找不到。
  • 手机「无线调试」必须开着；关了就没有 adbd 端口，找端口也找不到。
  • 网段里其它在线主机（电视、电脑、打印机）不列出，网段扫描只用于判断认得的设备是否还在线。
  • 端口扫 32768–65535，另补 5555；固定到其它低位端口的设备不保证能扫到。
  • 换网络后手机随机 MAC 会变：旧记录会表现为「没回应」+ 新地址「未识别」两行，靠找端口重新认领身份。

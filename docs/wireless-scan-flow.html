无线设备扫描流程

水月清影 ScreenZoom · 设计说明 · 2026-10-26
手机 IP 或端口变了，扫描能定位到它；找不回时，明确告诉用户下一步该做什么，而不是一直转圈。

为什么这样设计

  • 当前网络收不到设备的 mDNS 广播，靠广播发现不可行。
  • 部分开放端口不是 adb（例如 OPPO 的 46888）。adb connect 仍会提示 “connected to”，随后设备变 offline；旧逻辑把它当成成功。
  • 是否连上，不能看 adb 的提示语，只能看设备状态：只有 device 才算成功。
  • 换 IP 本身不会换端口；端口只在无线调试重启、开关或重新配对时变。两者经常一起变，所以旧端口只做一次快速尝试，不当主路径。

总流程

1点扫描 · 排除已连接设备
↓
2mDNS 收集（≤ 5 秒）· 收到广播就直接列出
↓
3地址簿逐台探活 · ping → 比对 MAC → 连接并验证
↓
4没连上 · ARP 扫本网段，按 MAC 找新 IP
↓
5新 IP + 旧端口 · 只试一次，不自动扫端口
↓
6仍失败 · 标记原因：IP 变了 / 端口变了 / 不在线 / 没有无线调试
↓

用户点「找端口」

定位当前 IP
试旧端口和 5555
只扫这一台的端口段
验证通过 → 连上

用户点「深度查找」

ARP 列出在线主机
扫全网段端口（可停止）
逐个连接并验证
找到 adbd → 连上
统一验证：adb connect → 轮询 adb devices： device = 成功；unauthorized = 找到但需授权；持续 offline = 立即断开并判失败。

三条路径

路径何时用做什么耗时停止
普通扫描 每次点扫描 / 切到无线页 广播 + 地址簿探活 + ARP 找新 IP + 试旧端口 5–10 秒 不需要
找端口 找到新 IP，但旧端口不通 定位当前 IP，失败只扫这一台 30–40 秒 可停止
深度查找 不知道设备在哪 / 没有身份信息 ARP 在线主机，扫全网段端口，逐个验证 1–2 分钟 可停止

普通扫描绝不自动进入端口扫描；启动自动重连失败也停下，等用户点「找端口」。

设备身份

身份优先级：serial → mDNS 实例名 → MAC（仅本网段）→ 旧地址。MAC 可能随机化，也可能因代理 ARP 重复，只当同网段线索，不单独合并设备。

{"addr":"192.168.3.12:35153",
 "mac":"42-57-f8-14-93-e1",
 "serial":"…","name":"RMX3366",
 "lastSeen":"2026-10-26T21:30:00"}

每次验证连接成功后才学习 MAC / serial / 名称；旧地址簿自动兼容，所有写回保留字段。

界面状态

状态卡片文案动作
已找到正常设备卡片连接
IP 变了，旧端口能连和上次的 IP 不一样，已重新连上连接
找到新 IP，旧端口不通已找到新 IP，端口可能也变了找端口
端口变了端口可能变了找端口
IP 被别的设备占用这个 IP 现在是别的设备找端口
完全没找到没有发现无线调试 + 三种原因深度查找 / 重启 adb

找回和深扫时，顶部显示「正在为 RMX3366 找端口… 37%」和「停止」，不铺每台设备的进度。

边界

  • 只处理本机所在 IPv4 /24；访客网络、AP 隔离、跨网段找不到。
  • 手机「无线调试」必须开着；关了就没有 adbd 端口，深扫也找不到。
  • 深扫只负责找到 adbd，不负责配对；出现 unauthorized 仍要在手机上允许。
  • 端口扫 32768–65535，另补 5555；固定到其它低位端口的设备不保证能扫到。

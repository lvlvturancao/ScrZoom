无线设备扫描流程

水月清影 ScreenZoom · 设计说明 · 2026-11-01
扫描分两段：先找人（设备在不在这个网里），再找门（它的投屏端口通不通）。两段都过了才点「连接」；第二段不过，就点「找端口」只扫这一台。

阶段二 · 找门：TCP + 真连验证

阶段一只回答"在不在"，不回答"能不能连"；阶段二只回答"能不能连"，不再重复找人。两段的开关、耗时、出错表现都是独立的，调优也分开调。

投屏期间设备列表照样每 6 秒刷新，但不再对正在投的这台跑 getprop、wm size 这类查询——它们会和视频流抢同一条 adb 通道。名字和分辨率沿用上一次读到的值；这一路结束后自动恢复完整查询，其它设备的信息最多缓存 20 秒。

阶段一 · 找在线设备

1排除已连接的设备
判据：已经连着的 IP 不再列出来；地址簿里同 IP 的旧条目也不再复核端口——端口探针结束会断开连接，正在用的连接不能被它掐掉
耗时：忽略不计
2两条线并行
做什么：收设备广播（mDNS）+ 逐个 ping 本网段
判据：广播两轮；网段 /24、并发 64、单台 350 毫秒
耗时：约 2–5 秒 可调 ①②
3归属：这是哪台设备
顺序：广播 → 同 IP → 同 MAC（换了 IP）→ 其余不列
判据：只认广播到的和地址簿里的，网段里其它主机（电视、电脑）不列
4判在线
判据：网段里 ping 到的算在线；没 ping 到的再复核一次
复核：被扫网段内的补两包，网段外的走完整复核；仍不通就落到「上次用过的设备」
耗时：1–3 秒 可调 ③

这一阶段产出的结果是"在线列表 + 每台的地址（IP:端口）"，端口对不对还没验证。

阶段二 · 确认端口

1先试旧端口
判据：700 毫秒连不上 → 「端口不通」（可能是端口变了，也可能无线调试被关了）
耗时：最多 0.7 秒 可调 ④
2通了就真连一次
判据：device = 端口可用；unauthorized = 需重新配对；连不上 = 端口不是无线调试
耗时：最多 4.5 秒 可调 ⑤
3扫描只验证，不替你连上
原因：验证用的临时连接验完就断，免得留下一堆会变成 offline 的空连接；连哪台、连不连，由你点「连接」决定
4结论缓存十分钟
原因：假端口会让连接卡十秒，命中缓存就不再重验
保存：port-probe-cache.json，重启程序也算 可调 ⑥
为什么要真连：TCP 通不代表是 adb。厂商自带的服务也占这类端口（实测 realme 的 46888：TCP 能连，adb connect 卡满十秒才失败），只看 TCP 就会把"端口不是无线调试"误报成"端口可用"。

③ 离线复核
网段内 PingQuick 两包 × 600 毫秒；网段外 PingAlive 单包 + 三包		 包数多 → 不误判掉线，扫描更慢（每台多 1–3 秒） PingQuick / PingAlive
④ 端口 TCP 探测 700 毫秒 调小 → 弱网下的真端口可能被误判成「端口不通」 ProbeAdbPort 里的 PortProbe(…, 700)
⑤ 真连验证：连接最多 2.5 秒、判定最多 2 秒 调大 → 慢设备不容易误判，但假端口会拖得更久；调小 → 慢速无线下的真设备可能被判"不是无线调试" ConnectVerified(addr, 2000, 2500)
⑥ 验证结论缓存十分钟，文件 port-probe-cache.json 调长 → 扫描更快，设备改了端口后显示会滞后；调短 → 更准，但每次都要重验 PortCacheFile / PortCacheTryGet
⑦ 网卡选择：过滤虚拟网卡、VPN、隧道口，优先地址簿所在的网段 开 VPN 或双网卡时若扫错网段，先查这里 GetLanTarget
⑧ 界面标签与按钮（端口可用 / 端口不通 / 端口不是无线调试 …） 调整文案或动作时只改前端 index.html 的 wifiRowHtml

实测：首次扫描约 10 秒（要真验端口），之后 6–7 秒（命中缓存）。扫描期间不清理 adb 里的 offline 记录（有查找任务在跑时跳过），免得打断正在验证的连接。

慢了先看哪

  • 日志出现 wifi-discover 无广播… → 阶段一卡在广播：先看手机无线调试是否开着、网络是否屏蔽组播。
  • wifi-discover 在线 N 台…广播条目 N 条，入列 N 台…网段在线主机 N 台 → 一眼分清是"广播没到"还是"网段没扫到"。
  • 总耗时（自检模式）明显变长时：若在线台数没变而时间涨了，多半是阶段二在验证假端口，看参数 ⑤ 和缓存 ⑥。

边界

  • 只处理本机所在 IPv4 /24，网关和本机自身不列出；访客网络、AP 隔离、跨网段找不到。
  • 手机「无线调试」必须开着；关了就没有 adbd 端口，找端口也找不到。
  • 端口扫 32768–65535，另补 5555；固定到其它低位端口的设备不保证能扫到。
  • 换网络后手机随机 MAC 会变：旧记录会表现为「没回应」，新地址靠广播直接出现，或手动填 IP 和端口。
  • 纯网络、又没收到广播时，"端口变了"和"无线调试没开"分不出来：IP 通只说明设备在局域网里，不代表 adbd 在听。现在只标「端口不通」，说明里写清两种可能，由「找端口」确认——扫到就是端口变了，扫不到多半是没开。这是已知短板，不自动扫端口。

# 投屏诊断面板

更新于 2026-11-02。对应功能：「正在投屏」列表每一行的「i」按钮，或直接点击该行。

## 用途

投屏出现音频卡断、画面掉帧或偶发断连时，先打开这一路的诊断面板，判断问题出在网络、手机负载还是电脑端读取。掉线现场日志只能事后看；这个面板给的是当时的数据。

面板只在打开时轮询：文字数据每秒刷新，设备侧数据每 5 秒采一次；关闭后 15 秒内停止，不额外占用投屏通道。

## 数据从哪来

| 分组 | 指标 | 来源 / 公式 | 节奏 | 局限 |
|---|---|---|---|---|
| 本次投屏 | 配置码率、帧率上限、视频缓冲、音频开关/编码/码率/缓冲 | 启动参数 | 静态 | 是上限，不是实测 |
| 本次投屏 | 实际帧率、每秒跳帧、每分钟跳帧 | scrcpy `--print-fps` 输出 | 1 秒 | 是渲染帧率，不等于编码帧率；静态画面会很低 |
| 本次投屏 | 编解码器 | 启动参数与 scrcpy 启动日志 | 启动 | 日志没有时按引擎默认显示 h264 / opus |
| 本次投屏 | 采集 / 窗口 | scrcpy 启动日志 `Texture …: WxH` 与本次启动的窗口尺寸 | 启动 | 采集就是引擎实际编码的画面尺寸；镜像档现在按窗口下发 `--max-size`，两者应接近 |
| 本次投屏 | 实测吞吐 | 设备 `wlan0` 收发字节差值 ×8 | 5 秒 | 含 ACK、重传和其它应用流量，是近似值 |
| 网络 | Ping 当前/平均/最大/抖动/丢包 | 本机 ICMP，2 秒一次 | 2 秒 | 是链路往返，不是画面端到端延迟；ICMP 可能被设备降优先级 |
| 网络 | TCP 连接数与状态 | 本机 `GetActiveTcpConnections` | 0.5 秒 | 只有状态，没有字节/RTT |
| 网络 | 投屏进程 CPU | 本机进程 CPU 时间差值 | 1 秒 | 判断电脑端读取/渲染是否被拖慢 |
| 设备无线 | RSSI、链路速率、频段、SSID | 设备 `cmd wifi status` | 5 秒 | 驱动平滑值；不支持时回退 `dumpsys wifi` |
| 设备无线 | 无线重试/秒、丢失/秒、累计重试率 | `retriedTxPackets`、`lostTxPackets` | 5 秒 | 部分 ROM 恒 0；漫游/重连会归零 |
| 设备无线 | adb 隧道 RTO/cwnd/ssthresh/重传 | 设备 `ss -tin` 匹配本连接端口 | 5 秒 | 一条隧道被该设备所有投屏路共享；重传字段只在发生过时出现 |
| 设备 | CPU 使用率 | `/proc/stat` 两次采样差值 | 5 秒 | 5 秒平均；首次采样没有上一份，显示 0 |
| 设备 | 负载 1/5/15 分钟、核数 | `/proc/loadavg`、`nproc` | 5 秒 | 负载包含不可中断/IO 等待任务，不等于 CPU 忙；以 CPU% 为准 |
| 设备 | 可用/总内存、交换使用/总 | `/proc/meminfo` | 5 秒 | `MemAvailable` 是内核估算；交换是 zram，占用高说明内存在换页 |
| 事件 | 启动、退出码、自动重连、掉线现场保存 | 程序内存事件环 | 事件驱动 | 最多 40 条 |
| 结束态 | 退出码、最后 12 行输出、事件 | 退出时快照 | 事件驱动 | 保留 60 秒；被同设备自动重连时跟到新一路 |

## 不采集什么，为什么

- **单连接 TCP 字节数、RTT、TCP 重传率**：Windows 要用 `SetPerTcpConnectionEStats` 启用采集，必须管理员权限。程序按普通权限运行，所以不碰；改用 Ping、无线重试/丢失和套接字 RTO 代替。
- **音频欠载计数**：scrcpy 只在 `-V debug` 日志里输出 `[Audio] Buffering … underflow=…`，默认不开启调试日志。面板显示音频配置和设备负载，配合无线重试/抖动判断音频卡断。
- **每路独立带宽**：一台设备只有一条 adb 隧道，所有投屏路共享；吞吐和 RTO 是设备级数据。

## 怎么看

- **音频卡断**：先分清楚是 CPU 还是等待。设备负载高但 CPU% 只有三成，说明任务卡在内存/IO 等待，不是 CPU 被占满；这时看交换使用，占用超过一半通常意味着在换页。无线重试要先和流量一起看：低流量下 10 包/秒、累计 10% 以内不一定就是瓶颈，丢包 0 时更可能是手机忙。
- **画面卡顿/掉帧**：看实际帧率、跳帧、投屏进程 CPU，再看「采集 / 窗口」。采集尺寸远大于窗口（例如窗口 491×1080、采集 1440×3168）说明手机在编码根本显示不出来的像素，编码器会被拖满；镜像档现在会按窗口尺寸下发编码上限，正常情况下两者接近。静态画面帧率低是正常的；游戏里掉到个位数才可疑。如果 Ping 抖动明显、跳帧断续出现，到「更多参数 → 视频缓冲」加 100 毫秒，画面会晚一点但更稳；玩游戏先留 0。
- **偶发断连**：看最近事件、TCP 状态、RTO 和掉线时的 Ping。面板打开期间掉线，会显示退出码和最后输出；同设备自动重连后会跟到新一路。

## 采样与开销

- 文字数据从程序内存读取，每秒一次，不走 adb。
- 设备侧每设备每 5 秒一条批量 shell（`cmd wifi status` + `/proc/net/dev` + `/proc/loadavg` + `/proc/meminfo` + `nproc` + `ip addr` + `ss -tin`），单条超时 6 秒，全局最多两路并发。
- 连续失败 3 次后该设备退避到 15 秒；关闭面板 15 秒后不再续期，空闲 30 秒后台循环退出。
- 设备侧命令会走同一条 adb 隧道，属于用户主动打开的诊断开销；不要长期开着面板玩游戏。

## 隐私

「复制诊断」生成的是纯文本，包含设备名、IP、SSID、BSSID、负载和事件，仅在用户主动点击复制时写入剪贴板。发给别人前先确认是否要保留热点名称和地址。

## 复核命令

```text
# 无线信号与重试
adb -s <设备> shell cmd wifi status

# 设备侧吞吐（两次取样算差值）
adb -s <设备> shell cat /proc/net/dev

# 负载与内存
adb -s <设备> shell cat /proc/loadavg
adb -s <设备> shell grep -E 'MemTotal|MemFree|MemAvailable|SwapFree' /proc/meminfo

# adb 隧道
adb -s <设备> shell ss -tin
```

面板数值与上面命令对不上时，先看面板的「设备侧数据已 N 秒没更新」提示；`cmd wifi status` 不支持时面板会标注来源为 `dumpsys`。
